# Native rendering notes

Use these checks for the relevant component family. They describe encountered mapping failures, not reasons to add compensating layout nodes.

- **CSS resolution:** Prefer rendered computed values. If using source CSS, parse it rather than applying URL/variable regexes. Resolve custom properties, inheritance, shorthand resets and declaration order before mapping. Preserve spaces between substituted values and encoded parentheses in media URLs.
- **Surface ownership:** Native controls may render wrappers, inputs, anchors and nested icons differently from the source DOM. Inspect the generated elements and documented style targets. Put a border/background on the actual shell once; avoid double borders.
- **Theme states:** A base `background-image: none` does not remove a theme's hover gradient. Set the observed state background/color/border/shadow on the surface owner. Check active/selected navigation controls too; source-transparent menus must not inherit a colored active button surface. Verify icon contrast with label contrast.
- **Style grammar:** Use typed props and documented style targets. State overrides use forms such as `button:hover.background-color`; breakpoint/state combinations must follow the current guide/parser. In the tested renderer, `wrapper:hover@tablet.flex` was accepted, while `wrapper@tablet:hover.flex` was not.
- **Typography:** Confirm font availability, weight and computed line height. A heading may not parse Markdown emphasis. Resolve important inherited text values and verify responsive theme overrides rather than assuming a desktop rule will remain authoritative.
- **Images:** Native image hosts can own dimensions. Avoid applying source panel constraints both to a layout wrapper and its nested image. Give each dimension one owner; preserve natural ratios for fixed-height logos. Copy observed image filters/opacity, including inverted logos. Verify every featured/media variant loads and has nonzero dimensions.
- **Native loops/carousels:** Props or JavaScript may calculate item widths and overwrite CSS flex rules. Use supported item-count/visibility props. Create separately scoped breakpoint instances only when documented responsive configuration cannot express the source behavior; record this decision and retain all items.
- **Card hover:** A sibling-resizing pattern needs a real flex parent and compatible base/hover flex values. Confirm generated display and resulting widths. For nested reveal content, supported inherited CSS custom properties can carry parent hover state; verify child opacity and touch behavior instead of relying on saved XML.
- **Buttons as links:** An external-navigation button may render an anchor. Verify competing link rules do not defeat responsive button widths or hover selectors. Use a scoped specificity correction only when a rendered conflict proves necessary.
- **Sticky/fixed regions:** Check ancestor overflow, containment and generated section positioning. Verify top-of-page and scrolled behavior. Preserve an observed overlap with CSS positioning and appropriate normal flow; do not solve it with arbitrary blank viewport-height elements.
- **Forms and dynamic assets:** A local submission table is not the source email provider. Required-field feedback is not proof of successful delivery. A static image is not verified Lottie/motion parity. Keep these distinctions in the manifest and handoff until the real behavior is mapped and verified.
- **Dialogs and consent controls:** A settings/open-dialog control needs its actual mapped behavior. Do not replace it with a link to an unrelated page. Check closing, keyboard access and focus ownership when supported; report an unavailable consent-manager integration instead of implying it works.
